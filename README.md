# CarMarketplace — каталог и маркетплейс подержанных автомобилей

![Python](https://img.shields.io/badge/Python-3.x-3776AB?logo=python&logoColor=white)
![Flask](https://img.shields.io/badge/Flask-3-000000?logo=flask&logoColor=white)

![React](https://img.shields.io/badge/React-18-61DAFB?logo=react&logoColor=black)
![Vite](https://img.shields.io/badge/Vite-5-646CFF?logo=vite&logoColor=white)
![MUI](https://img.shields.io/badge/MUI-v5-007FFF?logo=mui&logoColor=white)

Веб-платформа для просмотра, добавления и управления объявлениями о подержанных
автомобилях. Пользователи могут просматривать каталог, изучать карточки машин,
добавлять их в «Избранное», а администраторы — управлять каталогом автомобилей,
моделями и списком пользователей через интерфейс.

Проект состоит из двух частей:

- **Backend** — REST API на Python (Flask + SQLAlchemy), база данных SQLite.
- **Frontend** — SPA на React (Vite + Material UI).

## ✨ Возможности

**Для пользователя:**

- Регистрация и авторизация в системе.
- Просмотр каталога автомобилей в виде карточек.
- Детальная информация об автомобиле (год, пробег, состояние, цена, описание).
- Добавление автомобилей в «Избранное» и управление списком избранного.

**Для администратора:**

- Создание, редактирование и удаление автомобилей.
- Управление справочником моделей автомобилей (каталог брендов/моделей).
- Просмотр списка зарегистрированных пользователей.
- Пункты администрирования появляются в боковом меню только у админов.

## 🧠 Бизнес-логика

### Ролевая модель и разделение прав

Каждый пользователь имеет флаг `is_admin`. На основе этого флага фронтенд
определяет видимость административных разделов в боковом меню (`Wrapper.jsx`):
обычному пользователю доступны «Каталог», «Избранное» и «Добавить автомобиль»,
а администратору дополнительно показываются «Добавить модель», «Каталог моделей»
и «Список пользователей». Сама проверка прав выполняется фронтендом — бэкенд
на текущий момент не разграничивает доступ к админ-эндпоинтам (см. ограничения).

### Навигация через параметры маршрута

После успешной авторизации пользователь перенаправляется на маршрут
`/{userId}/catalog`, где `userId` — идентификатор пользователя из базы. Весь
интерфейс построен вокруг этого параметра: избранное (`/{userId}/favorites`),
редактирование авто (`/{userId}/edit-car/:id`), админ-разделы. Такой подход
проще сессионных cookie, но менее безопасен — идентификатор не защищён и виден
в URL.

### Каталог автомобилей

`Car` хранит ключевые атрибуты объявления: марка, ссылка на модель (`model_id`),
год выпуска, цена, пробег, состояние, описание и URL фотографии. Справочник
моделей (`CarModel`) отделён от самих автомобилей и содержит пару
«название модели + бренд», что позволяет переиспользовать модель для нескольких
машин и строить выпадающий список при создании объявления.

### Избранное (многие-ко-многим)

Связь «пользователь ↔ автомобиль» реализована через промежуточную таблицу
`FavoriteCar` с внешними ключами на `users.id` и `cars.id`. Бэкенд защищает
от дублей: повторное добавление одного и того же авто не создаёт вторую запись.
При получении списка избранного сервер подтягивает связанные данные автомобиля
и название его модели, возвращая удобный для фронтенда объект.

### Жизненный цикл объявления

Формы создания и редактирования автомобиля отправляют данные на `/api/cars` и
`/api/cars/:id`, после чего фронтенд возвращает пользователя в каталог. Удаление
доступно из формы редактирования. Аналогичным образом устроен справочник моделей
(`/api/models`) — он полностью поддерживает CRUD.

### Известные ограничения и точки роста

- Пароли хранятся в базе в открытом виде — необходимо хеширование (bcrypt/argon2).
- Аутентификация не защищает API-эндпоинты: права проверяются только в интерфейсе.
- `userId` передаётся в URL, что позволяет подменять контекст другого пользователя.
- Фотографии хранятся как URL в поле `photo`, загрузка файлов не реализована.
- Нет поиска и фильтрации по цене/году/пробегу.

## 🚀 Запуск проекта

Требования: **Python 3.10+**, **Node.js 18+** и **npm**.

### 1. Backend (Flask API, порт `5005`)

```bash
cd application/core

# создать виртуальное окружение
python -m venv .venv

# активировать его:
#   Windows (PowerShell):
.venv\Scripts\Activate.ps1
#   Windows (CMD):
.venv\Scripts\activate.bat
#   Linux / macOS:
source .venv/bin/activate

# установить зависимости
pip install -r requirements.txt

# запустить сервер
python main.py
```

Сервер будет доступен по адресу **http://127.0.0.1:5005**. База данных
`used_cars.db` создаётся автоматически при первом запуске в текущем каталоге
(уже заполненная копия лежит в `application/used_cars.db`).

### 2. Frontend (React + Vite)

```bash
cd web

# установить зависимости
npm install

# запустить dev-сервер
npm run dev
```

Приложение откроется по адресу **http://localhost:5173**. Страница `/:userId/catalog`
встанет на свой маршрут автоматически после входа.

### 3. Проверка

- Откройте `http://localhost:5173` — форма авторизации.
- Зарегистрируйтесь или войдите (например, тестовый пользователь
  `john_doe` / `password123` из скрипта наполнения).
- Просматривайте каталог, добавляйте авто в избранное.
- Ошибки удобнее всего отлаживать в консоли браузера — фронтенд логирует ответы API.

> **Подсказка:** при изменении кода в `web/src` Vite подхватывает изменения
> автоматически (HMR). Backend запущен в `debug=True` — сервер также
> перезагружается при правках `main.py`.

## 🔌 REST API

Базовый URL: `http://127.0.0.1:5005`

| Метод | Маршрут                          | Описание                                     |
| ----- | -------------------------------- | -------------------------------------------- |
| GET   | `/api/models`                    | Список всех моделей автомобилей              |
| GET   | `/api/models/<id>`               | Модель по ID                                 |
| POST  | `/api/models`                    | Создать модель                               |
| PUT   | `/api/models/<id>`               | Обновить модель                              |
| DELETE| `/api/models/<id>`               | Удалить модель                               |
| GET   | `/api/cars`                      | Список всех автомобилей                      |
| GET   | `/api/cars/<id>`                 | Автомобиль по ID                             |
| POST  | `/api/cars`                      | Создать объявление об автомобиле             |
| PUT   | `/api/cars/<id>`                 | Обновить объявление                          |
| DELETE| `/api/cars/<id>`                 | Удалить объявление                           |
| POST  | `/register`                      | Регистрация нового пользователя              |
| POST  | `/auth`                          | Авторизация (username + password)            |
| GET   | `/profile/<id>`                  | Профиль пользователя                         |
| GET   | `/users`                         | Список пользователей (для админа)            |
| GET   | `/api/favorites/<userId>`        | Избранные автомобили пользователя            |
| POST  | `/api/favorites/<user>/<car>`    | Добавить автомобиль в избранное              |
| DELETE| `/api/favorites/<user>/<car>`    | Убрать автомобиль из избранного              |

## 🗄 Модель данных

```
User (users)                    Car (cars)                    CarModel (models)
───────────────                 ─────────────                 ─────────────────
id (PK)                         id (PK)                       id (PK)
username (unique)               brand                         name
password                        model_id (FK → models.id)     brand
email (unique)                  year
avatar                          price                       FavoriteCar (favorite_cars)
first_name                      mileage                      ──────────────────────────
last_name                       condition                    id (PK)
birth_date                      description                  user_id (FK → users.id)
is_admin                        photo                        car_id  (FK → cars.id)
```

Связи:

- `Car.model_id` → `CarModel.id` (многие-к-одному).
- `FavoriteCar` — связующая таблица «многие-ко-многим» между `User` и `Car`.
